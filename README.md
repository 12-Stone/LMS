# Twelve Stone Academy

Twelve Stone Academy is the team's training and development hub, with courses, assignments, knowledge resources, and bulk course imports. Course files can be stored in a private Cloudflare R2 bucket and downloaded through authenticated app routes.

## Develop locally

```bash
cp .env.example .env
corepack enable
pnpm install
pnpm dev
```

`pnpm dev` skips sign-in for local preview only. Production uses the invite-only login flow. Do not expose the development preview when testing private course data.

Apply app migrations with `pnpm db:migrate`. Connect course storage in Bulk Import Studio using the shared storage form: choose Cloudflare R2, enter the S3 endpoint, bucket, and bucket-scoped Object Read & Write credentials, use region `auto`, and leave Public URL blank. Keep public bucket access disabled. Verify connection before importing. Course imports support files up to 5 GiB each using bounded 5 MiB multipart chunks, per-chunk retries, and cancellation; larger files are skipped. Incomplete or partially failed courses are not saved. Credentials are workspace-scoped, so configure them again under the production administrator or organization rather than copying development secrets.

## Deploy to an existing Railway project

`railway.json` builds the Node server and runs production migrations before each deployment. Railway does not load service variables from this file or automatically import environment files.

1. Add a persistent PostgreSQL service to the same Railway project and environment.
2. Import `railway.env.example` into the app service under **Variables → Raw Editor**. If the database service is not named `Postgres`, update the service name in the `DATABASE_URL` reference.
3. Before saving, fill `BETTER_AUTH_SECRET` with a fresh private value generated by `openssl rand -hex 32`. Keep this value stable across deployments and never commit a filled copy of the file.
4. Apply the variables and deploy. Railway retains them for subsequent deployments; the existing pre-deploy command applies the database migrations.

Only `DATABASE_URL` is needed on Railway; `NETLIFY_DATABASE_URL` is a Netlify alternative. No auth URL or bypass flag is required. Remove any production `AUTH_DISABLED` override so authentication stays enabled.

## Project layout

- `app/`: routes and UI components
- `actions/`: operations shared by the UI and the app's agent
- `server/`: server plugins and the database client
- `drizzle/`: schema and migrations; start with `drizzle/START_HERE.md`
